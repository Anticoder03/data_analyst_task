C. Create Reporting Views
[ ] Create a view showing students whose marks are above a selected threshold.

[ ] Write at least 3 SELECT queries using your views.
[ ] Explain how views simplify repeated reporting queries.

D. Understand SQL Indexes
[ ] Learn what an index is and how it can improve data retrieval.
[ ] Learn the difference between primary key, unique and regular indexes.
[ ] Use SHOW INDEX to inspect indexes on your tables.
[ ] Create a regular index on a frequently searched practice column such as `city`.
[ ] Create an index on a frequently filtered column such as `fee_status`.
[ ] Create a composite index on two suitable columns, such as `course_id` and `marks`.
[ ] Create a UNIQUE index on a suitable column such as email, if there are no duplicates.
[ ] Use SHOW INDEX again to verify the indexes.

E. Practise Index Management
[ ] Drop a practice index using DROP INDEX.
[ ] Verify that table data remains unchanged after dropping an index.
[ ] Explain why too many indexes can slow down INSERT, UPDATE and DELETE operations.
[ ] Explain why indexes are useful for columns frequently used in WHERE, JOIN and ORDER BY clauses.

F. Explore Query Execution Plans
[ ] Learn the purpose of EXPLAIN.
[ ] Run EXPLAIN on a query that filters students by city.
[ ] Run EXPLAIN on a query that joins students and courses.
[ ] Run EXPLAIN on a query that filters by two columns.
[ ] Identify the table, access type, possible keys, selected key and estimated rows in the output.
[ ] Learn the basic difference between a full table scan and index-based lookup.
[ ] Use EXPLAIN after creating an index and compare the execution plan.
[ ] Do not claim a query is faster based only on an estimated plan; record actual timing only if measured consistently.

G. Query Optimization Practice
[ ] Select only the required columns instead of using SELECT *.
[ ] Practise filtering rows with WHERE.
[ ] Check that JOIN columns have suitable indexes.
[ ] Avoid applying functions to indexed columns in WHERE conditions when a direct range condition can be used.
[ ] Use LIMIT when only a small number of rows are required.
[ ] Compare a subquery with an equivalent JOIN where appropriate.
[ ] Use EXPLAIN to inspect at least 3 queries.
[ ] Explain what you changed and why.
