B. Practice INSERT Statements

C. Practice UPDATE Statements
[ ] Update the city of one student using their student ID.
[ ] Update the fee status of selected students using a WHERE condition.
[ ] Update the fee amount for one practice course.
[ ] Run SELECT before and after each UPDATE to verify the change.
[ ] Practise updating multiple matching rows with a clear WHERE condition.

D. Practice DELETE Statements
[ ] Delete one test record using its unique ID.
[ ] Delete records matching a specific condition from a practice table.
[ ] Run SELECT before and after each DELETE to verify affected rows.
[ ] Demonstrate a safe workflow: SELECT the target rows first, then execute DELETE.
[ ] Never run DELETE without a WHERE clause on a table containing useful data.

E. Modify Table Structures with ALTER TABLE
[ ] Add a `phone_number` column to a practice students table.
[ ] Add a `created_at` column with an appropriate date/time data type.
[ ] Change the data type or size of a suitable practice column.
[ ] Rename a column using syntax supported by your MySQL version.
[ ] Rename a practice table.
[ ] Use DESCRIBE or SHOW COLUMNS to verify structural changes.
[ ] Practise dropping a column only from a temporary practice table after confirming it contains no required data.

F. Apply SQL Constraints
[ ] Create a practice table with a PRIMARY KEY.
[ ] Create a table with NOT NULL and UNIQUE constraints.
[ ] Add a DEFAULT value to a suitable column.
[ ] Add a CHECK constraint, such as marks being between 0 and 100.
[ ] Create a FOREIGN KEY referencing a primary key in another table.
[ ] Test valid inserts and observe what happens when you try invalid values.
[ ] Explain PRIMARY KEY, FOREIGN KEY, NOT NULL, UNIQUE, DEFAULT and CHECK in your notes.

G. Learn Transactions
[ ] Practise START TRANSACTION.
[ ] Make a test UPDATE and use ROLLBACK to undo it.
[ ] Start another transaction, make a safe test change and use COMMIT.
[ ] Verify the final data using SELECT.
[ ] Explain the difference between COMMIT and ROLLBACK.
[ ] Perform transaction exercises on tables using a transaction-safe engine such as InnoDB.

H. Understand Database Normalization
[ ] Learn why normalization reduces duplicate data and update anomalies.
[ ] Study First Normal Form (1NF): each field contains a single value and rows can be uniquely identified.
[ ] Study Second Normal Form (2NF): satisfy 1NF and remove partial dependency on part of a composite key.
[ ] Study Third Normal Form (3NF): satisfy 2NF and remove transitive dependencies.
[ ] Write one simple example of a table that violates 1NF, 2NF or 3NF.
[ ] Explain how splitting data into related tables can reduce duplication.
